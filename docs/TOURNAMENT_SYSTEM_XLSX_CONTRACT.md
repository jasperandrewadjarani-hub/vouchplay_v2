# Canonical Tournament-System XLSX - Compatibility Contract

Reference for the `TournamentSystemXlsxExporter` (handover §26.11, §26.11.1). This is the **locked
compatibility contract**: the export must reproduce this structure exactly, or the downstream JT
tournament system (P002 Pickleball Tournament System - the "PICPA" workbook) cannot ingest it.

**Source inspected:** `sample_data_/tournament_googlesheets_sample.xlsx` (444 KB, authored in Excel).
Inspected programmatically 2026-09-06 (unzip + XML parse; see the structural compatibility test which
regenerates and asserts this). **Never guess or silently change this schema** because VouchPlay's
internal DB changes (§26.11.1 step 7).

## Workbook

- **8 worksheets, LOCKED order:** `Standings`, `Matches`, `Teams`, `Players`, `Divisions`,
  `TournamentDates`, `Sponsors`, `Config`.
- Header row = row 1 on every sheet. Data starts row 2.
- Dates are stored as **Excel serial numbers** with a date number-format (not text).
- IDs are short prefixed strings: `DIV-01`, `TEAM-001`, `PLY-001`, `MATCH-<hex>`, `DATE-<hex>`.
- Filter ranges present on Matches/Teams/Divisions (informational; the exporter re-derives them).

## Sheets (headers in exact column order)

### 1. Standings  (A-I, 9 cols) - results, tournament-system-owned
`DivisionID | Pool | TeamID | Wins | Losses | PointsFor | PointsAgainst | Diff | PoolRank`
VouchPlay has no match results (Phase 12+). **Emit header row only.**

### 2. Matches  (A-S, 19 cols) - schedule/results, tournament-system-owned
`MatchID | DivisionID | Phase | Pool | Round | Team1ID | Team2ID | Court | ScheduledTime |
Team1Score | Team2Score | SetScores | WinnerTeamID | Status | BracketSlot | NextMatchID |
LoserNextMatchID | UpdatedBy | CompletedAt`
Brackets are generated by the tournament backend. **Emit header row only.**

### 3. Teams  (A-I, 9 cols) - VouchPlay OWNS
`TeamID | DivisionID | TeamName | Player1Email | Player2Email | RegisteredAt | Status | Pool |
EnteredBy`
- `TeamID` = `TEAM-001`.. (per-export sequential). `DivisionID` = `DIV-01`.. (matches Divisions sheet).
- `TeamName` = member surnames joined by `/` (e.g. `Al-Muqri/Zein`); singles = the one surname.
- `Player1Email`/`Player2Email` = member emails in member order (Player2 blank for singles).
- `RegisteredAt` = **Excel serial date** (`yyyy-mm-dd` display).
- `Status` = registration state title-cased to the system's vocabulary (`Confirmed`, `Waitlisted`,
  `Pending`, `Withdrawn`, `Rejected`). `Pool` = blank (tournament system seeds pools).
- `EnteredBy` = `VouchPlay Export`.

### 4. Players  (A-J, 10 cols) - VouchPlay OWNS
`PlayerID | FirstName | LastName | Nickname | Email | Phone | Gender | SkillLevel | RegisteredAt |
EnteredBy`
- `PlayerID` = `PLY-001`.. (per-export sequential). Distinct players across all confirmed teams.
- `Gender` = `Male`/`Female` (from profiles.sex) or blank.
- `SkillLevel` = the player's Community Skill band label (e.g. `Novice`), blank if unrated.
- `RegisteredAt` = **Excel serial date** (`m/d/yyyy` display in the sample; a date format either way).
- `Phone` = blank (VouchPlay does not collect phone in V1). `EnteredBy` = `VouchPlay Export`.

### 5. Divisions  (A-P, 16 cols) - VouchPlay OWNS the identity cols; bracket config = defaults
`DivisionID | Name | PlayType | SkillLevel | Status | NumPools | AdvancePerPool | PointsToWin |
WinBy | CreatedBy | PlayoffFieldMode | PlayoffFixedSize | ScoringRules | ScheduleBlocks | MaxTeams |
PlayoffSeeding`
- `DivisionID` `DIV-01`.., `Name` = composed division name, `PlayType`/`SkillLevel` = skill band label,
  `MaxTeams` = capacity_teams, `CreatedBy` = `VouchPlay Export`.
- Bracket/scoring config the tournament system needs but VouchPlay does not model
  (`NumPools`, `AdvancePerPool`, `PointsToWin`, `WinBy`, `Status`, `PlayoffFieldMode`,
  `PlayoffFixedSize`, `ScoringRules` json, `ScheduleBlocks` json, `PlayoffSeeding`): emit safe,
  documented **defaults/blanks** the organizer edits in the tournament system, never invented data.

### 6. TournamentDates  (A-C, 3 cols) - VouchPlay OWNS
`DateID | Date | Label`
- `DateID` = `DATE-001`.. (or hex), `Date` = **Excel serial date**, `Label` = `Day 1`, `Day 2`, ...
  derived from the tournament start..end date span (one row per day).

### 7. Sponsors  (A-C, 3 cols) - not modeled in V1
`SponsorID | Name | LogoURL`  - **Emit header row only.**

### 8. Config  (A-B, 2 cols) - key/value
`Key | Value`
- Emit non-sensitive tournament metadata: `ClubName`/`TournamentName`, `City`, `StartDate`, `EndDate`,
  `ExportedAt`, `Source=VouchPlay`, `SchemaVersion`.
- **NEVER emit secrets.** The sample contains an `AdminPassword` key - VouchPlay must not produce that
  or any credential (confidentiality rule); the tournament-system owner sets admin config on their side.

## Rules the structural compatibility test enforces (§26.11.1 step 6)

Fails the build if: a required sheet is missing, sheet order changes, any header cell text changes, a
required column is added/removed/reordered, the date columns stop being real dates, or the Status
vocabulary drifts. The test regenerates a workbook from a fixture snapshot and re-reads it (exceljs).
